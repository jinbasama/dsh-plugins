# 外部规则表

`custom.json` 是发现新坑时唯一需要改的文件。改这里不用动 JS、不用重新打包，重启宿主后生效。

## 什么时候该往这里加一条

满足任一条就加：

- 某个 PowerShell 写法在本机（Windows PowerShell 5.1 / PS 7 / GBK 控制台 / 受限沙箱）必然出错；
- 自动修复器改错过一次，需要留一条回归线；
- 同一个错误在两个不同任务里各犯过一次。

只要是一次性的判断失误，不要加——规则表只收「可复现、可正则描述」的坑。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `[A-Za-z][A-Za-z0-9_-]{1,31}`，不能与内置 R1–R22 重名 |
| `level` | 否 | `blocking`（`mode: deny` 下拒绝执行）或 `advisory`（默认） |
| `scope` | 否 | `code`（默认，先剥掉引号与注释再匹配）或 `raw`（对原文匹配） |
| `pattern` | 是 | 正则源码，长度 < 500；不支持 `g` 之外的全局状态 |
| `flags` | 否 | 只取 `i m s u` |
| `title` | 否 | `{ "zh": "...", "en": "..." }` |
| `fix` | 否 | 修复指引，同上双语 |
| `expect` | 建议 | `{ "match": [...], "clean": [...] }`，校验脚本会逐条断言 |

## 加一条的流程

1. 在 `custom.json` 追加一项，`expect.match` 写触发样例、`expect.clean` 写不应误报的样例；
2. 跑 `node scripts/validate-rules.mjs`（会校验 id、正则编译、与内置冲突、并按 `expect` 自测）；
3. 重启宿主，`pwsh_check` 即为生效状态。

## 边界

- 需要上下文判断（引号内外、AST、块结构）的坑不要塞进正则，那属于 `lib/rules.js` 的内置规则；
- `scope: code` 会把单引号内容一起剥掉，所以「双引号里的 `$var:`」这类真实陷阱要用 `raw` 或内置规则表达；
- 每条规则都要能被反例证伪，没有 `clean` 用例的规则先别加。
